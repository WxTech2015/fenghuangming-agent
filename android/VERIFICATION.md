## 安装问题修复

最初的手机日志中包管理器返回 `Failed transaction (2147483646)`，旧启动脚本随后退出。android.2 改用 Go 管道传输后，手机已进入包管理器安装逻辑，但末尾的 `-` 被当成未知选项，安装仍失败。

android.3 将命令修正为 `pm install -r --user 0 -S <字节数>`，省略 APK 路径，从标准输入读取。已核对 [Android 10](https://android.googlesource.com/platform/frameworks/base/+/refs/heads/android10-release/services/core/java/com/android/server/pm/PackageManagerShellCommand.java) 与 [Android 14](https://android.googlesource.com/platform/frameworks/base/+/refs/heads/android14-release/services/core/java/com/android/server/pm/PackageManagerShellCommand.java) 的安装和标准输入处理代码。命令继续使用独立管道，不把 `/data/adb` 中的日志或 APK 文件描述符传给 Binder。安装前后继续校验 APK 和应用 UID；失败不阻止守护启动，重复安装由进程锁拦截。

补充检查覆盖流式安装参数、字节完整性、损坏 APK 拦截、具体安装错误保留、输出上限与进程超时，以及安装失败后仍启动守护的 Shell 回归。Linux 另检查命令子进程接收的三个标准流确实是管道。开发机完成 Windows 用例及 Android 交叉编译，Linux 用例由 GitHub Actions 执行；目标手机上的实际安装结果仍待更新后确认。

本次先按 Android 选项规则复现旧命令的 `Unknown option -`，修正后相同用例通过。该检查验证命令契约，不等同于手机实际安装。

## android.6 后台保活

环境仍为 MuMu Android 15、x86_64、KernelSU 3.2.5，保持原有 Permissive 和系统媒体音量 0。通过 KernelSU 安装本版本测试 ZIP 并重启，APK、WebUI 和运行脚本与 ARM64 包一致，守护按相同源码编译为 x86_64。未连接华为手机。

本版本将监控及后续子进程迁出管理器 cgroup，隔离标准输入与会话，提高本模块 Root 进程的内存回收优先级。原生前台服务保持 CPU 与 Wi-Fi 锁；只添加本项目播放器的 Doze 白名单，卸载时仅移除模块添加的条目。关闭界面或移除任务不结束服务。守护与播放器不再因连续失败 5 次而放弃恢复，手动停用或禁用模块仍优先。

## Android 9 独立 SH 版

`0.2.0-android9.2` 增加自解包 SH 安装器与仅监听 `127.0.0.1:17789` 的本机网页控制台。程序放在 `/data/adb/fenghuangming/standalone`，原有配置与缓存保留。安装器实际在 Google AOSP Android 9 / API 28 x86_64 隔离模拟器中执行两次，首次安装及覆盖安装均完成 SHA-256 校验、普通 APK 安装与守护启动；测试包只替换守护为同源码 x86_64 文件和相应架构门槛。ARM64 程序完成 API 28 编译及 ELF 检查。

WebView 66 使用无 Root 桥接的普通应用宿主，直接打开真实本机 HTTP 控制台。14 项实际检查通过：鉴权页面、原生音频下载与播放、暂停、增加 1 秒、恢复、制动后原生待机、保存配置重新连接、停止守护但保留控制台、手动停止保持停用、通过 HTTP 再启动及日志页。回归修复了旧 WebView 在 `no-referrer` 策略下发送 `Origin: null` 的兼容问题，改用 `same-origin`，保持请求来源和管理密钥校验。

Go 测试覆盖来源 / Host / 密钥校验、管理操作白名单、私有文件拒绝与密钥持久化。APK 通过 Lint、单元测试和实际包信息检查，网页构建与协议测试通过。没有在华为真机执行，AOSP 测试镜像也未装 SukiSU 驱动；`service.d` 在目标手机是否会被自动执行仍未验证，安装说明提供手动启动入口。
